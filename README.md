# NetMind AI

NetMind AI 是一个面向 Windows 的中文智能流量分析工作台。当前版本提供完整可运行的桌面界面、独立捕获后台、HTTP/1.1 显式代理、可选的 HTTPS/HTTP 1.1 正文解密、确定性证据链展示、真实 AI 模型分析、脚本隔离验证，以及 SQLite 元数据、内容寻址正文存储和脱敏审计基础设施。

## 快速运行

环境要求：Windows 10/11、稳定版 .NET 10 SDK。仓库通过 `global.json` 锁定 10.0.302，不接受预览 SDK；.NET 10 是 LTS。

```powershell
dotnet run --project src/NetMind.Workbench/NetMind.Workbench.csproj
```

Release 构建：

```powershell
dotnet build NetMind.slnx --configuration Release
```

## 当前功能

- 全中文深色工作台，支持高 DPI 和响应式窗口缩放。
- 实时概览、流量探索、记录组、AI 分析、脚本验证、项目与数据、设置七个功能页。
- 实时概览与流量探索共享同一套流量列、资源图标和类型前景色；列采用连续固定布局，缩窄列宽时后续列同步补位。
- 两张流量表均支持右键当前记录，通过深色“选择过滤”子菜单按主机、类型、协议或方法快速进入流量探索，并可清除全部过滤条件。
- 工作台一键启动/停止独立 CoreHost，默认监听 `127.0.0.1:8877`。
- 一键打开独立配置的 Edge/Chrome 采集浏览器，只修改该浏览器进程的代理参数，不修改 Windows 全局代理。
- HTTP/1.1 显式代理端到端转发、正文大小限制、超时和并发边界。
- HTTPS 默认使用 `CONNECT` 加密隧道并只记录连接元数据；用户可在工作区明确启用独立 CA，对显式代理中的 HTTPS/HTTP 1.1 请求进行正文解密。同一 TLS 连接支持顺序复用，`Content-Length` 与 `chunked` 请求正文均会按边界读取并分别持久化。
- 基于 Windows TCP 所有者表关联真实客户端进程名和 PID，失败时明确显示“未知进程”。
- 模拟采集命令与实时数据库更新；按端点或进程筛选流量。
- HTTP 方法和状态码语义化配色，点击请求可查看可追溯证据。
- 流量探索支持从内容寻址存储读取真实请求/响应正文；未启用解密的 HTTPS CONNECT 明确保持正文加密。
- 流量表使用资源类型图标和整行前景色标识图片、接口数据、脚本、样式、字体、媒体、文档和连接，并可按同一分类快速筛选；选中行自动使用高对比文本。
- 响应标签页在响应头与原始正文之后提供安全预览：图片直接显示，JSON 格式化，HTML 仅提取文本且不执行脚本或加载远程资源。
- HTTP 事务可在本地查看原始 URL、查询参数、请求头、Cookie、请求正文、响应头和响应正文；用户显式发起 AI 分析时按需发送当前证据池的完整原始数据，审计日志和主动对外分享副本仍独立脱敏。
- HTTP 上游连接失败或超时同样会记录为 502 事务，保留失败请求证据，避免错误请求在采集列表中静默丢失。
- 流量证据字段支持鼠标框选和 `Ctrl+C`；选中事务后可复制完整原始证据、脱敏 JSON 或适用于 PowerShell 的原始 cURL。二进制正文、超大正文和 HTTPS CONNECT 会拒绝生成不完整的 cURL。
- 流量列表支持暂停显示刷新而不中断后台采集，并提示暂停期间新增的事务数量；恢复后一次同步并保留当前选择。
- 流量表将主机/域名与端点路径分列展示，并提供响应大小列；长内容使用省略号并可悬停查看。列表区收窄，为右侧证据检查器保留更多空间。证据检查器采用“请求 / 响应 / 相关数据”中文标签页，布局与浏览器网络调试工具一致。
- AI 分析页支持 DeepSeek Chat Completions 与 OpenAI Responses 两种接口；当前默认配置为 `https://api.deepseek.com` / `deepseek-v4-flash`。API 密钥只保存在 Windows 凭据管理器或由 `NETMIND_AI_API_KEY` 提供，设置文件和审计日志不保存密钥。
- 真实模型调用默认关闭，只有用户点击“开始新会话”或发送追问才联网；首轮发送确定性概况和事务摘要，模型通过工具批量读取相关完整事务、页内 Hook 或证据文件。支持取消、失败恢复、耗时/令牌统计、输出上限和截断提示。
- 流量表可逐条勾选 AI 分析范围；存在勾选时严格使用勾选集合，没有勾选时使用当前高亮及同主机上游补全（受证据上限约束）。AI 结果按 Markdown 原生渲染标题、强调、列表、引用、代码块和表格，关键结论使用 `[#序号]` 引用。
- 每次会话按工作区保存模板、范围、精确事务 ID、轻量工具证据账本、令牌计量与 Markdown 回复；可跨重启恢复和继续追问，上一轮工具原文不会在追问时重复上传。界面默认只渲染最近 12 轮，更早轮次分批展开，完整导出不受影响。
- 已持久化事务可以保存为记录组；记录组支持重命名、说明、追加/移除成员、历史恢复，并可导出含完整原始正文与 HAR 的 ZIP 或独立 HAR 1.2；全组或表中明确选择的事务可作为 AI 证据池（上限可配置，默认 30，最大 1000）。
- 采集浏览器的页内 Hook 覆盖页面、Dedicated/Shared Worker 与范围内 ServiceWorker；“采集自检”可一次核对代理、Hook 接收端、CDP、页面/Worker 挂载、TLS 信任与最近入库证据。
- 证据检查器使用统一 WPF 深色主题滚动条，支持滚轮、轨道翻页与拖动。
- Python 脚本编辑器顶部对齐、采用适中固定行高并提供关键字、字符串、数字、注释和内置函数着色；请求 Hook 支持隔离试跑及投递/处理/丢弃/错误/重启运行指标。
- 工作区清单、Windows SQLite 元数据、SHA-256 内容寻址 Blob 存储、JSONL 审计日志和敏感字段脱敏。
- 工作区提供默认不删除的项目级保留/容量策略、占用分类、孤儿 Blob 清理与 SQLite 压缩；支持完整敏感证据 ZIP 备份，以及校验格式/容量/路径穿越后导入为新项目。
- 工作区支持配置最多 200 条 HTTPS 加密直通域名，接受精确主机与 `*.example.com` 子域名规则；匹配连接保持端到端加密，只记录 CONNECT 元数据，适用于证书固定或不希望解密的站点。
- 工作区已成为可操作的项目容器：支持新建、切换和重命名，每个工作区独立保存流量数据库、正文 Blob、记录组与审计日志；采集或 AI 分析运行时拒绝切换。
- 独立 SandboxHost、Python 静态能力策略、隔离参数、最小化环境、输出上限，以及 Windows Job Object 强制的单进程、内存、CPU/墙钟和宿主退出自动终止边界。
- HTTP/2 帧、WebSocket 帧、SSE、gRPC envelope、DNS 问题与 Protobuf wire 字段的有界确定性解析。
- 端点参数规范化、聚类失败率/P95、稳定字段分类，以及关联原始事务的确定性证据准备。

启动时的示例列表会明确标记为“演示数据”。点击“开始采集”会切换到真实 HTTP/HTTPS 代理模式；需要将目标应用的 HTTP 和 HTTPS 代理设置为 `127.0.0.1:8877`，它不是透明抓包。
- 无第三方 NuGet 依赖，可离线构建。

## 项目结构

```text
src/
  NetMind.Core/          领域模型、模拟数据、工作区与安全存储
  NetMind.CoreHost/      独立 HTTP 代理捕获后台
  NetMind.SandboxHost/   独立 Python 验证后台
  NetMind.Workbench/     WPF 中文桌面工作台（GPU 合成与虚拟化列表）
  NetMind.SmokeTests/    无第三方依赖的核心冒烟测试
docs/
  installation.md        安装、运行和发布说明
  development.md         架构、设计规范和后续开发说明
```

底层静默抓包已支持配合采集浏览器密钥日志重组 HTTP/1.1、HTTP/2 与 HTTP/3；显式代理的主动 HTTPS 解密仍只协商 HTTP/1.1。HTTPS 解密默认关闭，只有用户在工作区确认后才会生成并信任当前工作区 CA；停用时会撤销当前用户根信任，程序不会绕过证书固定。

## 发布验证

```powershell
./packaging/publish-win-x64.ps1 -Version 0.8.0
./packaging/verify-release.ps1 -Version 0.8.0
```

发布脚本生成自包含 win-x64 目录、ZIP、SHA-256 文件和逐文件 `release-manifest.json`；验证脚本重新核对必需宿主、文件大小、SHA-256、未登记文件及调试产物。GitHub Actions 使用同一稳定 SDK 执行 Release 构建、完整冒烟、发布和清单验证。
