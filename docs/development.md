# 开发说明

## 设计原则

1. 确定性优先：协议解析、字段传播、证据生成和上下文裁剪必须先于模型分析。
2. 证据可追溯：事实结论需要指向来源、协议与字节偏移；无证据结论必须标记为假设或未知。
3. 默认安全：HTTPS 检查默认关闭，不自动安装证书；审计日志与对外分享副本仍走稳定脱敏；AI 分析在用户显式触发下发送完整原始流量数据（分析对象为测试账号数据，无需脱敏）。
4. 进程隔离：生成脚本和编译任务最终应由独立沙箱宿主执行，桌面进程只展示任务与结果。
5. 全中文界面：除品牌、HTTP 方法、协议名、进程名、代码和路径等不可翻译技术标识外，用户可见文案一律使用中文。

本地证据视图可以向工作区所有者展示原始 URL、参数、Header、Cookie 和正文。AI 分析经 `AiFullContextBuilder` 向模型发送完整原始证据（含正文、脚本与 Cookie 原值）：前提是用户确认分析对象为测试账号数据并显式触发，不再脱敏。进入审计日志或外部导出的数据仍必须通过独立隐私过滤器生成脱敏副本。钩子事件信封同样属于本地所有者视图：原始观察只允许投递给本机隔离的钩子工作进程，钩子产出的结论以 `hooks.finding` 审计事件落盘在工作区审计日志（与其他审计事件同走脱敏通道）。

剪贴板操作必须明确区分“原始证据”和“脱敏副本”。原始证据与原始 cURL 只由工作区所有者主动点击复制，并在界面提示可能包含凭据；用于外部分享的快捷复制默认使用 `AiPrivacyFilter` 生成脱敏副本；AI 分析直接发送原始证据。cURL 生成器不得输出 CONNECT 隧道、截断正文或无法无损表示的二进制正文。

模型网关的请求链路为对话式分层取证（旧一次性全量发送已移除）：首轮发送确定性证据池概况、#序号摘要（查询值不内联）和可用证据文件名，模型经 function calling 按需取数（`get_transactions`/`search_transactions`/`get_page_hooks`/`get_evidence_files`，事务应批量读取，单轮预算 8 MB、迭代上限 8 次）。单事务完整数据投影仍由 `AiFullContextBuilder` 构建（元数据、Header、Cookie、查询参数与正文，二进制正文转有界十六进制预览，正文按 Content-Type 过滤与截断），中文等内容不得转义为 `\uXXXX` 徒增令牌。证据文件是当前分析草稿，不在设置中跨重启恢复，工具只能按已添加文件名读取，禁止模型构造任意本地路径。会话以 JSONL 持久化到工作区，跨重启可继续追问；长期历史只保存用户问题、最终回答和轻量 `AiToolTrace`，其 `evidence-ledger` 只携带工具引用、结果规模与 SHA-256，绝不重复发送上一轮工具原文；需要细节时重新调用只读工具。模板内置 5 套，目录落盘在工作区 `ai-prompts.json`；未改动的 v1 内置模板用精确哈希迁移到新版证据约束，用户改过的模板继续保留。远程网关仅允许 HTTPS，本机回环测试服务可使用 HTTP。密钥使用 Windows Credential Manager Generic Credential `NetMind AI / 模型网关`，普通 JSON、命令行、审计日志和界面状态不得回显密钥。模型调用必须由用户明确点击触发，并支持取消、超时、响应大小限制和输出截断提示。

AI 证据池来自显式勾选集合、记录组或当前高亮事务（沿用 `GetAiEvidence` 的自动补全语义）；池内序号从 1 起与首轮摘要一致并按采集时间递增（工作台流量列表、概览健康度与记录组均带序号列且时间升序、最新在最下），取数工具的序号必须可映射回事务 Guid，无效序号要明确拒绝而不是静默忽略。模型 Markdown 只能转换为本地 WPF 文档元素，不执行 HTML、脚本、远程图片或链接导航。

页内 JS Hook 是采集链路的可选增强，任何失败不得影响抓包：注入经采集浏览器回环调试端口（CDP `Page.addScriptToEvaluateOnNewDocument`），接收端点仅监听 127.0.0.1；上报事件入库前必须完成单条截断、NUL 剔除与单批上限，总量超限同事务淘汰最旧；清空记录时联动清空，定向删除事务不联动。

记录组只保存当前工作区中已持久化事务的 GUID 引用，不复制原始正文。恢复记录组时必须按 ID 从 SQLite 精确查询；已清理或缺失的事务不得用演示数据替代。整组分析和组内选中分析必须复用 AI 的统一证据池范围函数及证据条数上限（1000），切换为普通勾选范围时应显式清除记录组范围。

工作区是顶层隔离边界。每个工作区拥有独立的 `metadata.db`、`blobs`、`traffic-groups` 与 `logs`；模型网关非敏感配置和 Windows 凭据属于当前 Windows 用户的全局配置。工作区切换必须在采集和 AI 调用均停止时执行，并同步清空旧流量选择、会话筛选、记录组内容及 AI 范围后再加载新工作区，禁止旧对象跨工作区复用。

AI 历史属于工作区数据，保存于 `ai-history/<id>`。`metadata.json` 只记录端点主机、模型、范围、事务 GUID、计量和响应标识，`evidence.json` 保存实际发送的完整证据快照（上限 16 MB，超限拒绝写入），`result.md` 保存模型原始 Markdown。历史写入必须先完成临时目录全部文件再原子移动，读取必须验证 GUID 路径、字段范围和大小上限。导出只包含历史元数据与 Markdown 结果。

对话式会话保存于 `ai-conversations/<id>.jsonl`。新会话必须持久化创建时的系统提示和每条消息的写入时间；长期历史保留全部用户/助手消息与 `AiToolTrace` 轻量取数记录，不重复保存工具返回原文。完整对话导出必须经 `AiConversationExportFormatter` 流式写入 Markdown，并对 JSON 属性、Header、Cookie、URL 查询值和普通命名值调用导出专用脱敏，不得直接复制 JSONL 原文。

## 协议解析器

`ProtocolParsers` 提供无模型参与、带输入上限和边界检查的确定性解析：

- HTTP/2：9 字节帧头、类型、标志、31 位流标识与载荷边界。
- WebSocket：FIN、RSV、操作码、扩展长度、掩码还原和控制帧约束。
- SSE：事件、数据、标识和重试字段。
- gRPC：压缩标志、5 字节 envelope 头与消息边界。
- DNS：消息头、压缩名称和问题字段，并限制指针跳转次数。
- Protobuf：varint、64 位、长度限定和 32 位 wire 字段。

解析异常统一抛出中文 `InvalidDataException`，不得把不完整输入解释为有效证据。

## 确定性分析

- 端点规范化会将数字、GUID、长十六进制和不透明标识段替换为 `{id}`，查询参数只保留排序后的键。
- 聚类按方法、规范端点和协议分组，计算请求量、错误率、平均延迟和 P95。
- 字段传播按名称与真实值确定性分组，对外只返回稳定 SHA-256 占位符和事务/偏移证据，不返回敏感原值。

工作台使用 WPF 保留模式渲染。流量表格必须开启行列虚拟化与回收，证据检查器通过数据绑定更新；定时刷新使用 SQLite 写入游标读取新增/完成态变更并保持用户选择，仅在删除、游标回退或超大积压时回退最近窗口，不得空闲时全量重读、强制选择最新事务、重建整个页面或在缩放期间生成截图。AI 长会话只渲染最近 12 轮，更早轮次按页展开，完整历史仍用于持久化和导出。

证据检查器不得显示 Windows 原生浅色滚动条。所有 `ScrollViewer`、表格和代码编辑器统一使用 WPF 深色滚动条资源；不得在窗口移动或缩放期间生成页面截图、调用 GDI 拉伸、同步刷新或重建页面。

真实正文必须通过 `StoredTrafficRecord` 的 SHA-256 引用从工作区 Blob 目录读取。读取路径必须验证哈希格式并限制预览大小；本地所有者界面可以展示原始文本，AI 上下文原样发送原始正文，进入审计日志或外部导出前必须调用稳定脱敏，二进制只显示有界十六进制预览。HTTPS CONNECT 不得把加密字节解释为正文。

响应可视化必须放在响应头和原始正文之后，不能遮蔽证据本体。图片预览最多读取 4 MB，并使用内存缓存完成解码后释放源流；JSON 允许展示层本地解码、着色与折叠（含超限子项省略提示与长值截断），但解码结果只服务于界面展示，不得影响存储、审计与复制路径，原始字节必须在这些路径中直通保留；HTML 仅提取安全文本，禁止创建浏览器控件、执行脚本或发起远程资源请求。无法识别或不安全的二进制类型只显示中文状态说明。

流量资源分类必须由响应 `Content-Type`、请求方法和端点扩展名确定，列表图标、整行前景色与类型筛选必须共享 `TrafficRow.ResourceKind`，不得维护多套可能分歧的映射。类型色应使用适合深色背景的低饱和高可读色；选中单元格必须恢复主题高对比前景。脚本编辑器使用 `RichTextBox` 本地着色，不加载第三方网页编辑器；编辑内容始终顶部对齐，固定行高保持在接近正文字号的可读范围，着色过程不得改变脚本文本。

实时概览与流量探索必须保持相同的列语义、顺序、紧凑宽度、文本省略提示、资源图标和行样式。中间列不得使用会把右侧列固定在远端的星号宽度；用户缩窄任一可调整列时，后续列应连续向左补位。列顺序固定，避免拖动列头时误改变两张表之间的字段对应关系。

流量表右键必须先选中鼠标所在记录，再从同一 `TrafficRow` 生成主机、类型、协议和方法过滤值。快速过滤应清除可能排除当前记录的旧来源、状态和会话条件，导航到流量探索并保持原记录选中；菜单与子菜单必须使用完整深色模板，不能混入系统浅色图标槽。

HTTPS 解密必须保持默认关闭。每个工作区使用独立 CA，私钥只保存到当前用户个人证书存储，根信任只加入当前用户存储；启用和撤销都必须由工作区页显式触发并写入审计日志。动态站点证书必须校验 CONNECT 主机并写入 SAN，TLS 内部 Host 必须与 CONNECT 目标一致。当前 ALPN 只声明 HTTP/1.1，不得把 HTTP/2 或 HTTP/3 误报为已解密；不得忽略真实上游证书错误或绕过客户端证书固定。

解密后的 HTTP/1.x 必须按连接语义循环读取，不能在每个 keep-alive 请求后强制断开客户端 TLS。请求正文只接受单一 `Content-Length` 或单一最终 `chunked` 边界，两者并存、未知传输编码、超限块、无效 CRLF 和超限 trailer 必须在 TLS 内返回 400 并保存失败证据。转发前必须移除 `Connection` 指定字段以及代理鉴权、传输编码、升级和其他逐跳头；缓冲后的响应使用确定的 Content-Length 返回。

## 分层

- `NetMind.Core` 不依赖 WPF，负责领域模型、工作区、内容寻址存储、脱敏审计、AI 完整上下文构建、静默抓包解析与演示数据。
- `NetMind.CoreHost` 是独立进程，负责显式代理、静默抓包、会话生命周期和流量持久化；运行异常通过中文标准错误和非零退出码报告。
- `NetMind.SandboxHost` 的 `run` 动词只接收暂存作业 JSON，执行静态能力检查，并在随机临时目录中以隔离参数启动 Python；Python 必须加入 kill-on-close 的 Windows Job Object，限制为单进程、有限内存、CPU 时间和墙钟时间。`hook-worker` 动词则拉起长驻钩子工作进程（默认只观察、受控 store 持久化；脚本用模块级 `INTERCEPT` 声明规则后，命中的请求才阻塞等待裁决并可改写向下传播），契约见 `docs/scripting.md` 的请求钩子章节。验证脚本的 fixture 契约、输出契约与资源限制见 `docs/scripting.md`。
- `NetMind.Workbench` 负责中文桌面界面、交互状态与数据可视化。
- `NetMind.SmokeTests` 以普通控制台程序验证核心安全不变量，避免引入外部测试包。

## 视觉规范

- 背景使用深墨色，卡片通过 1 像素低对比边框区分，不使用大面积纯黑。
- 青绿色代表主要操作和安全状态；蓝色表示读取；紫色表示 AI；黄色表示警告；红色表示失败。
- 所有页面保持 24–26 像素主留白，卡片圆角为 10–12 像素。
- 文字默认使用“微软雅黑 UI”，代码编辑器使用 Cascadia Code。
- 表格中的 HTTP 方法和状态码使用语义色，选中态必须保留可读对比度。

## 本地验证

仓库锁定稳定版 .NET SDK 10.0.302。若本机只有预览 SDK，先安装官方稳定 SDK；不要修改 `global.json` 让预览版混入发布产物。

```powershell
dotnet build NetMind.slnx --configuration Release
dotnet run --project src/NetMind.SmokeTests/NetMind.SmokeTests.csproj --configuration Release
```

开发期只对修改涉及的项目做 Debug 定向构建，并用 `--ai-only`、`--settings-only`、`--silent-only` 等定向开关验证对应不变量；全量 Release 构建与完整冒烟只在功能最终落地时执行。

冒烟测试由注册表驱动，不引入第三方测试框架：

- `--list` 列出全部套件、定向开关与是否进入默认全量运行。
- 不带参数运行默认全量套件；可同时指定多个定向开关，只跑选中的套件。
- 单个套件失败不会中止整轮：每个套件独立捕获异常，逐个报告通过/失败与耗时，
  末尾统一汇总并打印失败堆栈，**退出码等于失败套件数**（0 表示全绿）。
- 未知开关直接以退出码 2 报错，不会静默回退成默认全量——否则容易误以为定向验证已经跑过。
- `--page-hook-live` 需要真实 Chromium，标记为可选，不进默认全量运行。

新增能力时在注册表里加一条 `SmokeSuite`（名称、定向开关标签、执行体）即可，
套件必须自带工作区创建与清理，不依赖其他套件的执行顺序或残留状态。

## 后续集成边界

当前交付已经支持 HTTP/1.1 显式代理、HTTPS `CONNECT` 加密隧道元数据采集、用户明确启用的 HTTPS/HTTP 1.1 解密，以及基于 WinDivert 的底层静默抓包（被动嗅探、TCP/QUIC 重组与 HTTP 配对，配合 SSLKEYLOGFILE 实现 TLS/HTTP2/HTTP3 解密），并保留模拟数据用于无网络演示。透明捕获后续范围为 ETW 进程生命周期跟踪与重定向恢复；代理转发路径的 TLS 解密后续范围仍为 HTTP/2 ALPN/HPACK 与 HTTP/3（静默抓包路径已实现）。SandboxHost 已实现独立进程、隔离参数、环境清理、静态策略、输出上限和 Windows Job Object 资源强制，生产加固仍需 AppContainer 或受限令牌与文件 ACL。接入这些能力时不得改变默认关闭、显式授权和不绕过证书固定的安全原则。

显式代理接受 IPv4 连接后通过 Windows `GetExtendedTcpTable` 将客户端源端点关联到进程名和 PID。该结果属于连接时刻的本机元数据；查询失败或使用尚未支持的 IPv6 连接时必须使用“未知进程”，不得沿用演示进程名。

采集浏览器必须使用独立用户数据目录和进程级 `--proxy-server` 参数，不得修改系统代理。Chromium 启动参数必须包含 `--disable-quic`，避免 HTTPS 流量绕过 TCP `CONNECT` 隧道；不得加入忽略证书错误或绕过证书固定的参数。静默抓包模式下还需为浏览器进程注入指向工作区 `keys/sslkeylog.txt` 的 `SSLKEYLOGFILE` 环境变量（仅该进程生效，不触碰全局环境），使采集后台能解密该浏览器的 HTTPS 正文；两端路径由 `SilentKeyLogRelativePath` 常量锁死，缺一端即退化为隧道模式。

Windows 系统代理只在用户于设置页显式开启“无感抓包”后由采集会话接管：接管前必须先写入哨兵快照，停止时按快照还原，异常退出后下次启动依据哨兵恢复，接管与还原均写入审计日志。钩子系统必须保持默认关闭、默认只观察、故障无感直通；只有脚本用模块级 `INTERCEPT` 显式声明规则时，命中的请求才阻塞等待裁决并允许改写，未命中的流量仍是即发即忘。裁决超时、工作进程崩溃或改写超限一律按原样放行，不得阻塞浏览器；落库记录实际上线的字节并保留改写前的原始内容，证据链不因改写而失真。加密隧道不可钩。

## 底层静默抓包

静默抓包以 WinDivert 网络层被动嗅探（`WINDIVERT_FLAG_SNIFF`）实现：只捕获报文，绝不拦截、修改或重注入。依赖 `WinDivert.dll` 与 `WinDivert64.sys` 随采集后台部署和管理员权限；依赖缺失、权限不足或驱动被安全策略阻止时必须给出中文指引，不得静默失败。

采集模式开关保存在工作台设置（默认关闭，走回环代理模式），勾选即保存，下次开始采集生效。静默模式以提升权限（UAC runas）启动 `NetMind.CoreHost silent`；提升后无法重定向 stdout，就绪/失败事实统一写 `%LocalAppData%\NetMind\silent-ready.json` 信号文件供工作台轮询，停止以 `silent-stop.signal` 信号文件通信；采集后台启动前必须清理旧停止信号，退出前清理两个信号文件，启动失败写 `silent-capture.start-failed` 审计事件。

报文解析、TCP 重组与 HTTP 配对必须是无驱动依赖的纯逻辑，可脱离真实网卡定向测试：按四元组维护双向流，序号比较必须回绕安全，乱序缓冲有界、超限标记流损坏而不是无限堆积；HTTP/1.x 按 `Content-Length`、`chunked` 与“读到关闭为止”三种正文语义增量配对请求与响应。TLS 流默认只记录隧道元数据与 SNI；命中工作区 SSLKEYLOGFILE（`keys/sslkeylog.txt`，采集后台增量读取）中的密钥时按记录层解密（TLS 1.2/1.3），明文按 ALPN 重组：http/1.1 复用现有配对，h2 经 HPACK 解码与帧重组为事务。QUIC（UDP 443）Initial 包用 RFC 9001 派生密钥无密钥解密提取 SNI/ALPN，1-RTT 包用流量机密解密并重组 STREAM 帧；ALPN 为 h3 时经 QPACK（静态表 + 单向编码器流维护的动态表）与 HTTP/3 帧层重组为事务。缺密钥、解密失败或格式错误必须退回隧道模式继续抓包，绝不中断；任何解码器损坏只影响对应连接上下文。隧道记录必须在识别到 ClientHello 时立即落库，不得等待流结算（浏览器长驻复用连接，等结算会导致活跃期间无条目可见），结算阶段不得重复落库。结算出的事务复用 `TrafficArchive` 持久化路径，会话模式标记为“底层静默抓包”，流表、空闲淘汰与单流缓冲均受集中常量限制。
